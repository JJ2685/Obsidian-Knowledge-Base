# 凝思服务器序列号弹窗与重启断网（initramfs 时序根治）

## 0. 结论摘要
- **问题现象**：每次重启后弹出「凝思产品授权管理」窗口要求输入序列号，且网络不通需人工恢复；输入序列号后网络也未必恢复。
- **直接影响**：重启即失联 + 现场误操作风险。
- **根本原因**：已确认——序列号本身有效（绑定板载网卡 MAC），问题是**开机时序**：initramfs 里只有 r8169 驱动，新 PCIe 网卡先注册抢占 eth0 名字，序列号校验（按 eth0 的 MAC）失败，linx_sec 拒绝网络配置；yt6801 接口注册被拖慢 400+ 秒。
- **最终处理**：三层修复——initramfs 预加载 yt6801 + 拷贝 udev 命名规则（根治）、udev 自动 ifup、rc.local 兜底（后被 ensure-eth0.service 取代）。
- **当前状态**：已根治。重启后网络约 1 分钟全自动恢复，序列号校验开机即通过，不再弹窗。
- **可复用方案**：[[RB-Linux-凝思开机网络自动恢复]]

## 1. 问题背景
- **问题发生前做过什么操作**：2026-10-29 加装 PCIe 千兆网卡（Realtek RTL8168，02:00.0）。
- **连带影响**：网卡接口命名变化（r8169 先抢 eth0 后被改名为 eth1）；显卡 PCI 位置 04:00.0 → 05:00.0，Xorg BusID 失效（图形桌面再次起不来）；原静态 IP .200 被别的设备占用（改为 .250）。

## 2. 环境信息
| 项目 | 信息 |
|---|---|
| 网卡 | 板载 yt6801（01:00.0，MAC 1c:83:41:f5:00:c7）= eth0；PCIe r8169（02:00.0）= eth1 |
| 序列号 | 17508BDE49415576，绑定 eth0 MAC（`get_linxsninfo -s` → `sn_text: 1C8341F500C7`） |
| 安全模块 | linx_sec（校验通过前拒绝网络配置） |

## 3. 根因链（修复前开机时序）

| 时间 | 事件 | 后果 |
|---|---|---|
| initramfs | 只有 r8169，它先注册并抢占 eth0 名字 | eth0 = 新卡（MAC 与序列码不符） |
| 1.5s | networking 服务执行 `ifup eth0` | linx_sec 校验失败 → `RTNETLINK: Operation not permitted` |
| 1.9s | udev 把新卡改名为 eth1 | ifup 已失败且不会重试 |
| 1.9s 后 | yt6801 驱动加载，接口注册延迟 400~600 秒（名字冲突拖慢） | eth0 长时间不存在 |
| 图形登录后 | checksn.sh → check_old_sn.py 校验失败 | 弹出 modifysn 授权窗口 |

关键结论：**序列码没坏**。校验逻辑：eth0 接口的 MAC 必须等于序列码绑定的 MAC。只要 eth0 = 板载卡，校验必过（实测 check_old_sn.py 返回 0）。新网卡不需要装驱动（内核 r8169 已完整支持）。

## 4. 实际解决过程（三层）
1. **initramfs 时序根治**：`/etc/initramfs-tools/modules` 追加 `yt6801`；新增 hook 把 `/etc/udev/rules.d/70-persistent-net.rules`（按 MAC 固定命名：板载=eth0、新卡=eth1）拷进 initramfs；`update-initramfs -u`。效果：开机早期新卡直接命名 eth1；序列号校验 1.9 秒即通过；yt6801 注册从 400+ 秒缩短到 36 秒。
2. **udev 自动配网**：`99-auto-ifup-eth0.rules` 接口出现时自动 ifup（带 60 秒重试）。
3. **兜底**：ensure-eth0.service（详见 [[INC-20261030-Linx-重启后网络不自动恢复]]）。

> 凝思的 initramfs-tools hook-functions 是精简版，没有 `copy_file` 函数，hook 里要用 `$DESTDIR` + `cp` 拷贝文件。

## 5. 验证结果
- [x] 重启后 ~1 分钟网络自动恢复，默认路由自动存在，DNS 正常
- [x] 序列号校验开机即通过，不再弹窗（修复前后开机日志逐项对比确认）
- [x] 多次重启稳定

## 6. 回滚方案
- initrd/grub 备份在 `/boot/initrd.img-*.bak-20261030`、`vmlinuz-*.bak-20261030`，可回退。

## 7. 经验总结
- **这次最关键的判断依据**：dmesg/syslog 时间戳对齐（网卡注册 vs networking 执行 vs linxsn 校验）还原完整时序。
- **下次优先检查什么**：`ifup` 报 `Operation not permitted` 先查安全策略/序列码状态，不是配置语法错误；弹授权窗查 `/etc/xdg/autostart/checksn_mate.desktop` 触发链。
- **不建议重复尝试的操作**：反复输入序列号；自行改 grub 的 linx_serial；在没理顺命名前反复改 interfaces。
- **还需要补充的知识**：initramfs 构建机制、udev 持久命名规则。
