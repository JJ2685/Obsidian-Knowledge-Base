# 凝思服务器重启后网络不自动恢复（网卡迟到 36 秒）

## 0. 结论摘要
- **问题现象**：每次重启后必须在本机手动 `ip link set eth0 up` + `ifup eth0` 才能远程连接；`networking.service` 显示 SUCCESS 但 eth0 无地址无路由。
- **直接影响**：重启即失联，现场运维负担重。
- **根本原因**：已确认——板载 yt6801 网卡驱动加载后接口注册延迟 36 秒，`networking.service` 在 eth0 还不存在时就执行完了 `auto eth0`。
- **最终处理**：新增 `ensure-eth0.service` systemd 兜底服务（10 分钟重试）；根因（initramfs 时序）随后在 [[INC-20261030-Linx-序列号弹窗与重启断网]] 中彻底解决。
- **当前状态**：已解决（兜底 + 根治双保险）。
- **可复用方案**：[[RB-Linux-凝思开机网络自动恢复]]

## 1. 问题背景
- **问题发生前做过什么操作**：加装 PCIe 网卡（r8169）后，开机时新卡先抢 eth0 名字、udev 再改名。
- **是否可以稳定复现**：是（每次重启稳定复现）。

## 2. 现象与根因
从 `/var/log/syslog` + `dmesg` 还原的开机时序：

| 开机后 | 事件 |
|---|---|
| 1.470s | yt6801 板载网卡驱动加载（MAC 1c:83:41:f5:00:c7，与凝思序列码绑定） |
| 1.483s | r8169 扩展卡先抢到 eth0 名字 → 随即被 udev 改名为 eth1 |
| **36.054s** | yt6801 才真正注册成 eth0 接口（`fxgmac_open callin`） |
| 37.60s | eth0 链路协商完成 |
| 更早（<36s） | `networking.service` 已执行完 |

**结论**：`networking.service` 运行时 eth0 不存在，`auto eth0` 的 ifup 无从执行，之后无任何机制补配。

> 网卡注册延迟来自 out-of-tree 驱动 `yt6801.ko`（MotorComm v1.0.34）的 PHY 初始化等待。

## 3. 此前两个兜底为何失效
1. **udev 规则**（接口出现时自动 ifup）：`systemd-udevd: timeout ... killed`——udevd 等待子进程管道超时后将其杀掉。
2. **/etc/rc.local 后台重试循环**：rc-local.service 为 oneshot，主进程退出后 systemd 按 KillMode 清理残留后台子 shell。

## 4. 实际解决过程
新增 `/usr/local/sbin/ensure-eth0.sh`（60 次 × 10 秒重试：检测接口存在 → 拉链路 → 补 ifup → 地址+路由齐备即退出）与 `/etc/systemd/system/ensure-eth0.service`（oneshot + RemainAfterExit，After=networking.service）。完整脚本与单元文件见 [[RB-Linux-凝思开机网络自动恢复]]。

**关键点**：用 systemd 服务承载重试，进程生命周期受管，不会像 rc.local 后台进程那样被杀。

## 5. 验证结果
- [x] 重启后约 96 秒网络自动恢复（`ensure-eth0: eth0 配置成功(第 1 次检查,约 10 秒)`）
- [x] `inet 192.168.0.250/24` + `default via 192.168.0.1` 自动存在
- [x] 顺带验证 nouveau 硬件加速重启后仍生效

## 6. 经验总结
- **下次优先检查什么**：开机后"地址有、接口 DOWN、无默认路由" → 查 `/var/log/syslog` 中 networking 报错与网卡注册时序（dmesg 时间戳）。
- **不建议重复尝试的操作**：把重试逻辑放 rc.local/udev 里（都会被 systemd 杀掉）；反复改 interfaces 配置。
- **还需要补充的知识**：systemd 单元生命周期与 KillMode 语义。
