# 凝思图形桌面无法启动（Xorg 配置语法错误）

## 0. 结论摘要
- **问题现象**：图形桌面无法启动，只能使用文本终端登录；`systemctl restart display-manager` 无输出。
- **直接影响**：服务器只能本机文本操作，图形程序无法运行。
- **根本原因**：已确认——`/etc/X11/xorg.conf.d/20-modesetting.conf` 第 2 行 `Identifier` 前多了一个点（`.Identifier`），Xorg 配置解析失败。
- **最终处理**：重建配置文件、核对行号、重启 lightdm。
- **当前状态**：已解决（后续 2026-10-30 进一步切到 nouveau 硬件驱动，见 [[INC-20261030-Qt-图形界面卡顿高延迟]]）。
- **可复用方案**：[[RB-Linux-Xorg图形桌面故障排查]]

## 1. 问题背景
- **所属项目/设备**：凝思工作站服务器（电网频率响应系统）。
- **使用场景**：本机运行 Qt WebEngine 监控程序需要图形桌面。
- **问题发现时间**：2026-10-29。
- **问题发生前做过什么操作**：配置 `20-nouveau.conf` / `20-modesetting.conf` 试图启用图形驱动。
- **是否可以稳定复现**：是（配置文件错误固定触发）。

## 3. 现象与复现步骤
### 实际结果
`/var/log/Xorg.0.log` 关键报错：
```text
Parse error on line 2 of section Device in file
/etc/X11/xorg.conf.d/20-modesetting.conf
".Identifier" is not a valid keyword in this section.
(EE) Problem parsing the config file
(EE) no screens found(EE)
```

### 排查顺序
1. 尝试 nouveau 配置 → `(EE) No devices detected.`（当时 BusID 写 `PCI:4:0:0`，后证实是错的，见 [[INC-20261030-Qt-图形界面卡顿高延迟]]）。
2. 改用 modesetting 配置 → 报配置解析错误，定位到 `.Identifier` 语法错误。

## 4. 根本原因分析
- **已确认事实**：Xorg 日志明确报 `20-modesetting.conf` 第 2 行非法关键字。
- **根本原因**：配置文件粘贴/编辑时 `Identifier` 前多了一个点，Xorg 解析失败 → no screens found。
- **证据**：`/var/log/Xorg.0.log` 原文。

## 5. 实际解决过程
详见 [[RB-Linux-Xorg图形桌面故障排查]] 的标准步骤：备份旧配置 → heredoc 重建文件 → `cat -n` 核对行号 → `systemctl reset-failed lightdm && systemctl restart lightdm` → 按日志判断。

## 6. 验证结果
- [x] 修正后图形桌面正常启动（后续会话验证）
- [x] 重启后仍然正常
- 注意：本次只是修掉语法错误；真正的硬件加速问题到 2026-10-30 才解决（nouveau + BusID 修正）。

## 7. 经验总结
- **这次最关键的判断依据**：Xorg 日志第一个 `(EE)` 就是直接原因，不要跳过日志瞎猜。
- **下次优先检查什么**：`tail -n 100 /var/log/Xorg.0.log` 找首个 `(EE)`；`cat -n` 核对配置文件行内容。
- **不建议重复尝试的操作**：不装闭源 NVIDIA 驱动；不同时改多个配置文件；不在未核实 BusID 时照抄配置。
