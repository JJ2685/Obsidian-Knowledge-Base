# eth1 数据网口与数据通信网关联网调试

## 0. 结论摘要
- **问题现象**：eth1（数据网口）一开始 NO-CARRIER 无 IP，链路建立后工作站仍收不到任何网关数据。
- **直接影响**：tn_frequency 收不到实时数据（UDP 11002）。
- **根本原因**：初步判断——链路层问题（物理链路未通/未上电）已解决；收不到数据是**网关侧尚未配置数据上报目标**，工作站侧（链路 + IP + 防火墙）均已就绪。
- **当前状态**：工作站侧配置完成，等待网关侧配置（192.168.0.250:11002）。后网络重构：网关改接 eth0 网段（192.168.0.252），见 [[服务器网络拓扑结构变更记录]]。
- **可复用方案**：[[RB-Linux-凝思工作站SSH远程连接配置]]（网络排查部分）

## 1. 问题背景
- **使用场景**：工作站通过第二个网口 eth1 经交换机连接数据通信网关，供 tn_frequency UDP 通道使用。
- **是否可以稳定复现**：—

## 2. 环境信息
| 项目 | 信息 |
|---|---|
| 网卡 | eth0 yt6801（管理网 192.168.0.250）；eth1 RTL8168（数据网，配 192.168.1.250/24） |
| 数据通信网关 | 192.168.1.253（MAC 0c:86:29:d8:ad:4f），禁 ping |
| 其他 | PIX-LINK USB 无线网卡接 eth0 供外网，对系统透明 |

## 3. 排查过程
| 顺序 | 排查假设 | 执行操作 | 观察结果 | 判断 |
|---|---|---|---|---|
| 1 | eth1 无链路 | ip link / ethtool | NO-CARRIER、无 IP | 支持 |
| 2 | 固件缺失 | 查 /lib/firmware | rtl8168h-2.fw 缺失（仅致 PHY 非最佳态） | 排除（非主因） |
| 3 | 物理链路 | 现场接线、上电、插紧 | 黄灯亮，1000Mb/s Full，carrier=1 | 解决 |
| 4 | 网关地址 | 全段并行 ping 扫描 | 仅 192.168.1.253 回 ARP（禁 ping 但二层可达） | 确认 |
| 5 | 数据是否到达 | eth1 抓包 15s+9s+25s | 网关未主动发出任何帧 | 网关侧未配置 |
| 6 | 防火墙 | iptables | 已放行网关来源 UDP 11002 并持久化 | 就绪 |

## 4. 已落地的配置
- `/etc/network/interfaces` 新增 eth1 静态配置（auto eth1，192.168.1.250/24）。
- 防火墙：`ACCEPT udp from 192.168.1.253 dport 11002` + 其余 `DROP`，持久化到 `/etc/iptables.up.rules` + rc.local 恢复。
- NFS：挂载点已建，fstab 注释版挂载段就绪（`_netdev,noauto`），待网关导出共享。

## 5. 仍未确认的原因
- 网关侧数据上报目标与协议细节（IEC 60870-5-104 / Modbus TCP / 自定义 UDP 待确认）。

## 6. 经验总结
- **这次最关键的判断依据**：抓包"零帧"证明二层链路 OK 但对方不发数据——问题在网关侧，不在工作站。
- **下次优先检查什么**：链路灯与 carrier；`tcpdump -i ethX -n -e "ether src <网关MAC>"` 看对方是否真的发帧。
- **还需要补充的知识**：工业网关常见协议与"禁 ping 但 ARP 可达"的判断方法。
