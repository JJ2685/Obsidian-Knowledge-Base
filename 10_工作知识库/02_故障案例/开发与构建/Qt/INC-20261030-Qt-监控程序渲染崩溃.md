# Qt 监控程序在国产 CPU 上渲染崩溃（LLVM ERROR）

## 0. 结论摘要
- **问题现象**：Reqlian_frequency / tn_frequency（Qt WebEngine 程序）启动后崩溃退出，日志报 `LLVM ERROR: Cannot select: intrinsic %llvm.x86.sse41.pblendvb`（Qt 5.12 时代）；Qt 5.15 时代直接 SIGSEGV。
- **直接影响**：监控程序完全无法运行。
- **根本原因**：已确认——Xorg 无硬件 GL（modesetting 驱动不支持 DRI2），GL 回退到 Mesa 10.3 的 llvmpipe 软件渲染，其内置 LLVM 3.5（2014 年）不认识海光 CPU（Zen 架构，2017 年）；Qt 5.12 内置 SwiftShader（LLVM 3.9）同样不认 Zen。
- **最终处理**：Qt 5.15.2 运行库 + 修正 qt.conf + `GALLIUM_DRIVER=softpipe`（纯 C 软件光栅器，无 LLVM）。
- **当前状态**：已解决（后随 [[INC-20261030-Qt-图形界面卡顿高延迟]] 进一步启用硬件加速）。
- **可复用方案**：[[RB-Qt-海光CPU图形渲染问题排查]]

## 1. 问题背景
- **使用场景**：U 盘成品（Reqlian_frequency-fan-v2.1，Qt 5.11 编译）安装到服务器，启动即崩溃。
- **是否可以稳定复现**：是（海光 CPU + 老 Mesa 组合必现）。

## 2. 环境信息
| 项目 | 信息 |
|---|---|
| CPU/架构 | 海光 C86-3350（AMD Zen 架构） |
| 操作系统及版本 | 凝思 V6.0.8（Debian 8 / glibc 2.19） |
| 软件及版本 | Qt 5.12.12 / 5.15.2 运行库、Mesa 10.3.2、Xorg 1.16.4（modesetting） |
| 关键依赖 | libxkbcommon、libdbus、libxcb-util 等（均需手工补齐） |

## 3. 现象与复现步骤
- 程序能启动到 WebEngine 初始化，随后崩溃退出，日志最后固定为：
  ```
  QXcbIntegration: Cannot create platform OpenGL context, neither GLX nor EGL are enabled
  Sandboxing disabled by user.
  ```
- Qt 5.12 时代崩溃报 `LLVM ERROR: Cannot select: intrinsic %llvm.x86.sse41.pblendvb`。

## 4. 排查过程
| 顺序 | 排查假设 | 执行操作 | 观察结果 | 判断 |
|---|---|---|---|---|
| 1 | 缺 Qt 运行库 | ldd 检查 | 缺 7 个库（WebEngineCore 等） | 支持→下载 Qt 官方 7z 包 |
| 2 | 7zz 解压后缺库 | 补 libstdc++（CXXABI_1.3.9） | 服务器 GCC 4.9 太老 | 支持→conda-forge 补 |
| 3 | apt 装依赖 | apt-get install p7zip | 卡死 | 排除 apt（源只有 DVD，读光驱空转） |
| 4 | llvmpipe 崩溃 | 实测渲染 | LLVM ERROR（LLVM 3.5 不认 Zen） | 支持 |
| 5 | --disable-gpu 绕过 | Qt 5.12 + --disable-gpu | 触发 SwiftShader LLVM ERROR | 排除（Qt 5.12 时代） |
| 6 | 换 Mesa 18.3 + libglvnd | 替换客户端库 | glXChooseVisual 拿不到 visual | 排除（与 X 服务端 10.3 libglx 不兼容） |
| 7 | qt.conf 路径 | strace 追踪 | 5.15 程序从 5.12 目录加载 xcb 插件 | 支持→修正 Prefix |
| 8 | softpipe | GALLIUM_DRIVER=softpipe | 页面正常加载，零崩溃 | 采用 |

## 5. 根本原因分析
- **根本原因**：服务器上没有任何一个能用的 GL 渲染实现——X 无硬件 GL + llvmpipe/SwiftShader 内置 LLVM 不认识海光 Zen 架构。
- **证据**：Xorg 日志 `AIGLX: Screen 0 is not DRI2 capable`；崩溃日志 LLVM ERROR；gdb/strace 定位。

## 6. 实际解决过程
1. 服务器直接下载 Qt 5.12.12 官方 7z 包（Linux 解压，规避 Windows 提取丢符号链接）。
2. 补齐运行库到 `/opt/qt-runtime-lib/`（glibc 2.19 兼容构建）。
3. 修正 `/usr/sbin/qt.conf` 与 `/opt/tn_frequency/bin/qt.conf` 的 `Prefix = /opt/Qt5.15.2`。
4. 启动脚本加 `export GALLIUM_DRIVER=softpipe`。

**启动脚本关键行**（详见 [[RB-Qt-海光CPU图形渲染问题排查]]）：
```sh
export LD_LIBRARY_PATH=/opt/Qt5.15.2/lib:/opt/qt-runtime-lib:$LD_LIBRARY_PATH
export QTWEBENGINE_CHROMIUM_FLAGS="--no-sandbox"
export GALLIUM_DRIVER=softpipe
```

## 7. 验证结果
- [x] tn_frequency 页面标题加载成功，主进程 + 4 个 WebEngine 子进程存活，零崩溃
- [x] Reqlian 登录界面正常显示（截图确认）
- [x] 未引入新的异常（OpenSSL 版本警告为已知遗留，仅影响 HTTPS）

## 8. 经验总结
- **这次最关键的判断依据**：LLVM ERROR 的 intrinsic 名指向 CPU 指令选择失败 → LLVM 版本与 CPU 架构不匹配。
- **下次优先检查什么**：国产 x86（海光/兆芯）上 Qt/Chromium 渲染崩溃，优先考虑 llvmpipe/SwiftShader 的 LLVM 版本；qt.conf 的 Prefix 指向。
- **不建议重复尝试的操作**：在 Windows 上解压 Qt 7z 包（丢符号链接）；用 apt 装包（DVD 源空转）。
- **还需要补充的知识**：Mesa 软件渲染后端差异（llvmpipe vs softpipe vs SwiftShader）。
