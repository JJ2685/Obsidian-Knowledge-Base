# 凝思服务器无法编译 Qt 程序（商用许可墙 → Docker 编译 → SIOF 崩溃）

## 0. 结论摘要
- **问题现象**：服务器上 qmake 报 `Qt license file was not found! License check failed`，无法编译 tn_frequency 新版源码；绕过后又遇启动即 SIGSEGV。
- **直接影响**：程序改造无法在服务器落地。
- **根本原因**：已确认——① 服务器 Qt 5.12.12/5.15.2 均为商用预编译版，内置 licheck64 许可校验（与镜像来源无关），apt 源只有 DVD（Qt 5.3.2 无 WebEngine）；② 编译成功后启动崩溃是 `appconfig.cpp` 静态初始化顺序 fiasco（SIOF）。
- **最终处理**：CentOS 7 VM 上 Docker 跑 Ubuntu 20.04 + `qtwebengine5-dev`（Qt 5.12.8 开源）编译；uic 失效改手写 `ui_mainwindow.h`；SIOF 调整常量定义顺序。
- **当前状态**：已解决，v2 版程序生产运行。
- **可复用方案**：[[RB-Qt-无许可环境编译Qt程序]]

## 1. 问题背景
- **使用场景**：新版源码（2018 原版 + appconfig 通信改造）需要从源码编译成 Linux 二进制。
- **问题发生前做过什么操作**：上次安装的是成品二进制（全程没编译，未触发许可校验）——"上次能装"与"这次要编译"是两回事。

| 4 | 重新下载官方 7z 包 | 清华镜像 Qt 5.12.12 | 仍含 licheck64，报同样错 | 确认许可校验与来源无关 |

## 4. 根本原因分析
- **许可墙**：Qt 5.12+ 官方在线仓库的预编译二进制统一内置 licheck64 校验；只有源码编译（-opensource）或 apt 发行版开源包免许可。
- **SIOF**：`UdpServerIP` 等 `QString` 静态成员的初始化值引用了定义在后面的 `DEFAULT_*` 常量（非字面量类型运行时构造），静态初始化时 DEFAULT 尚未构造，`RefCount::ref()` 访问空指针崩溃。

## 5. 实际解决过程
1. **Docker 编译环境**：镜像改 `docker.m.daocloud.io/library/ubuntu:20.04` 显式地址；apt 切阿里云源；`DEBIAN_FRONTEND=noninteractive` + tzdata 预置；包名是 `libqt5webchannel5-dev`/`libqt5websockets5-dev`（带 lib 前缀）。
2. **uic 绕过**：uic 因 SYSV ABI 加载 libQt5Core 失败（qmake/moc/rcc 正常）→ 手写 `ui_mainwindow.h` + Makefile 把 uic 命令替换为空操作。
3. **csvread.cpp** 加 `#include <cmath>`（fabs 未声明）。
4. **SIOF 修复**：`DEFAULT_*` 常量定义移到依赖它们的成员定义之前。
5. 产物拷回服务器，启动脚本用 Qt 5.15.2 运行库（与旧版一致，规避海光 SwiftShader 问题）+ `GALLIUM_DRIVER=softpipe`。
6. **界面修复**：源码自带 index.html 是测试页，完整监控界面从旧版 `/opt/html/` 复制到 `/opt/tn-frequency-v2/html/`（js 的 ws://localhost:2018 与后端完全兼容）。

## 6. 验证结果
- [x] 主进程 + 4 个 WebEngine 子进程存活
- [x] UDP 11002 监听（`*:11002`）
- [x] WebSocket 2018 监听（`127.0.0.1:2018`）
- [x] config.ini 正确加载（UdpServerIP 等四项）
- [x] 完整监控界面正常显示
- ⚠️ OpenSSL 版本警告（已知遗留，仅影响 HTTPS）

## 7. 经验总结
- **这次最关键的判断依据**：区分"编译"与"运行"——服务器缺的是编译环境（许可），不缺运行库。
- **下次优先检查什么**：qmake 报许可错先 strace 看 licheck64 找什么文件；启动 SIGSEGV 先用 gdb 看栈（SIOF 特征：_GLOBAL__sub_I_ + RefCount）。
- **不建议重复尝试的操作**：伪造/空 .qt-license 文件（报 Invalid license key）；复用旧 Makefile（混有 Qt6/MSVC 生成物）。
- **还需要补充的知识**：Docker seccomp 与 PTRACE 诊断权限；SYSV ABI 与 glibc 版本关系。
