# Qt 监控界面卡顿高延迟（软件渲染 + 配置冲突）

## 0. 结论摘要
- **问题现象**：电网控制系统（tn_frequency，Qt WebEngine）运行时图形界面严重卡顿、高延迟，页面渲染极慢。
- **直接影响**：操作体验不可用。
- **根本原因**：已确认——两层叠加：① Xorg 用 modesetting 驱动无硬件 GL，整个系统 OpenGL 走 Mesa softpipe 单线程纯 C 光栅器；② `/etc/X11/xorg.conf`（nouveau 无 BusID）与 `20-modesetting.conf` 并存冲突，硬件驱动方案从未生效。
- **最终处理**：Xorg 切 nouveau 硬件驱动（BusID 修正为 PCI:5:0:0）+ 启动脚本加 `--disable-gpu`（Skia 多线程 CPU 光栅）。
- **当前状态**：已解决。tn_frequency 主进程 CPU 43.4% → 约 1%，页面约 45 秒完整渲染，操作流畅。
- **可复用方案**：[[RB-Qt-海光CPU图形渲染问题排查]]

## 1. 问题背景
- **使用场景**：softpipe 方案（见 [[INC-20261030-Qt-监控程序渲染崩溃]]）让程序跑起来了，但 1080p 页面每帧渲染极慢。
- **是否可以稳定复现**：是。

## 4. 根本原因分析
- **根因 1**：modesetting 驱动过老（无 glamor/DRI2）→ AIGLX 强制软件渲染。
- **根因 2**：xorg.conf 与 xorg.conf.d 配置冲突，CTO 写的 nouveau 配置从未生效。
- **根因 3**：Chromium 83 与老 Mesa 不兼容（offscreen FBO 失败反复重试）→ 白屏数分钟。
- **为什么 --disable-gpu 安全**：历史记录中 SwiftShader LLVM 崩溃发生在 Qt 5.12 时代；当前 Qt 5.15.2 实测无崩溃。

## 5. 实际解决过程
1. 备份并停用冲突配置（xorg.conf 清空、20-modesetting.conf 改名 .bak-softpipe）。
2. 新建 `20-nouveau.conf`（BusID `PCI:5:0:0`），重启 lightdm，验证 `AIGLX: Loaded and initialized nouveau`。
3. 启动脚本 `QTWEBENGINE_CHROMIUM_FLAGS="--no-sandbox --disable-gpu"`（tn/reqlian 两个脚本，旧版备份 .bak-softpipe）。
4. 保留 `GALLIUM_DRIVER=softpipe` 作为硬件 GL 失效时的兜底。

## 6. 验证结果
- [x] tn_frequency 主进程 CPU 43.4% → 约 1%（稳定态 0.6%）
- [x] 页面 45 秒内完整渲染（标题栏、导航、图例、坐标轴齐全；曲线区空白是网关未推数据）
- [x] 重启后 nouveau 硬件加速持久生效
- [x] 未引入新的异常

## 7. 额外发现：两个程序不能同时运行
tn_frequency 与 Reqlian_frequency 都把 `127.0.0.1:2018` 作为页面数据 WebSocket 端口，同时运行时后启动者白屏。日常只运行 tn_frequency（详见 [[00_项目总览]]）。

## 8. 经验总结
- **这次最关键的判断依据**：改动前先建性能基线（CPU 43.4%），每次只改一个变量并截图留证。
- **下次优先检查什么**：Xorg 日志 AIGLX/DRI2 段；`lspci` 核实显卡当前 PCI 位置（加装设备后会变）。
- **不建议重复尝试的操作**：SSH 里 `pkill -f tn_frequency`（杀掉自己）；截屏不先解锁屏保（全黑误判渲染失败）。
- **还需要补充的知识**：Skia 光栅与 GL 合成路径差异。
