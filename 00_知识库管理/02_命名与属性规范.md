# 命名与属性规范

## 一、文件命名

| 笔记类型 | 推荐命名 | 示例 |
|---|---|---|
| 工作问题案例 | `INC-日期-系统-现象.md` | `INC-20261029-Linx-LightDM桌面无法启动.md` |
| 标准解决方案 | `RB-领域-主题.md` | `RB-Linux-GT730图形桌面故障排查.md` |
| 项目档案 | `项目名-项目总览.md` | `广播电视管理系统-项目总览.md` |
| 学习章节 | `第XX章_章节主题.md` | `第01章_电路基本概念.md` |
| 学习知识点 | `知识点名称.md` | `电感与电容.md` |

- 工作案例建议加日期或编号，便于区分多次事件。
- 长期维护的标准方案不加日期，持续更新同一篇。
- 知识点名称尽量简短、唯一、可搜索。

## 二、通用属性

所有笔记尽量统一使用以下英文属性名，属性值用中文或通用技术名称：

| 属性 | 用途 | 示例 |
|---|---|---|
| `type` | 笔记类型 | `work_case`、`runbook`、`learning_concept` |
| `status` | 当前状态 | `resolved`、`verified`、`learning` |
| `created` | 创建日期 | `2026-11-03` |
| `updated` | 最近更新日期 | `2026-11-03` |
| `domain` | 所属领域 | `linux`、`qt`、`hardware`、`power_system` |
| `project` | 关联项目 | `项目A` |
| `source` | 学习资料来源 | `《电路》第六版` |
| `tags` | 少量检索标签 | `work/incident`、`learn/concept` |

## 三、状态值（受控）

建议控制状态值，避免同一含义出现多种写法：

- 工作案例：`investigating`（排查中）、`resolved`（已解决）、`blocked`（受阻）、`unverified`（尚未验证）。
- 标准方案：`draft`（草稿）、`verified`（已验证）、`deprecated`（已废弃）。
- 学习笔记：`not_started`、`learning`、`practiced`、`mastered`。

## 四、约束

- 不要一开始就设计几十个属性。先保证 `type`、`status`、`created`、`updated` 和必要的领域/项目属性稳定可用。
- 新增属性时先在这里登记，保持全库一致。
