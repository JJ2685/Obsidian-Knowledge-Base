# 文件架构与分类规范

> 文件夹负责大类归档；Properties 负责结构化信息；双向链接负责关联项目、案例、方案和知识点。

## 一、目录结构

```text
Obsidian知识库/
│
├── 00_知识库管理/              ← 入口、规范、模板
├── 01_收集箱/                  ← 快速记录，定期整理
├── 10_工作知识库/              ← 案例、方案、项目档案
├── 20_学习知识库/              ← 技术栈、课程、知识点
├── 30_资料库/                  ← 原始资料
├── 90_附件/                    ← 图片、截图、PDF
└── 99_归档/                    ← 已结束、过期、暂停的内容
```

## 二、分类规则

- **项目档案**：记录项目背景、架构、环境和入口索引，不把每次故障细节都堆进项目总览。
- **故障案例**：一篇笔记对应一次真实发生的问题，保留当时的环境、日志、排查顺序、实际改动和验证结果。
- **标准解决方案**：把一个或多个案例中验证有效的方法抽象成可重复执行的 SOP/Runbook。案例链接到方案，方案也反向列出来源案例。
- **技术规范与环境**：记录特定项目或设备的版本、依赖、硬件配置、网络拓扑等基线信息，方便排查时对照。不要记录密码、密钥或其他凭据。
- **学习知识库**：按技术栈或专业领域组织。一本书/一门课有章节索引；具体知识点拆成独立笔记，并从章节页链接过去。
- **资料库**：存放原始资料、官方手册和外部链接。不要把原始资料全文复制进知识笔记；知识笔记应写自己的理解和提炼。
- **收集箱**：先快速记录，定期整理。不要让收集箱成为长期堆积区。

## 三、新建目录的时机

- 项目级目录（`01_项目档案/项目名/`）：接手或启动真实项目时创建。
- 章节级目录（`电路原理/第XX章_.../`）：开始学习该章时创建。
- 不要一开始就创建大量空文件夹，先用几个真实案例和学习章节验证结构，再调整目录。

## 四、隐藏目录与插件目录

| 目录 | 用途 |
|---|---|
| `.copilot/`、`.opencode/` | Copilot / OpenCode 插件的内部运行数据（点开头，不出现在 Obsidian 文件列表） |
| `.git/` | 版本库元数据（Obsidian Git） |
| `90_附件/插件库/` | Copilot 对话记录、自定义提示词、AI 记忆、项目与 skills；Excalidraw 图纸、模板与脚本 |

这些目录由插件管理，不纳入知识分类，也不需要手动整理。`.obsidian/workspace.json` 等运行时状态不纳入版本管理（见 `.gitignore`）。
